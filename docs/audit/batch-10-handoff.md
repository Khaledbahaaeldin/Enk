## 1. What exists

### Task 27: F-Droid readiness and packaging
- Release build: R8 minify and resource shrink on, `vcsInfo.include = false`, `dependenciesInfo` off for APK and bundle, signing from `keystore.properties` or `ENK_KEYSTORE_*` environment variables (unsigned when neither exists), Gradle wrapper checksum pinned. `app/proguard-rules.pro` has no rules: the release build was walked on the emulator and Room, DataStore, Glance and the credits assets all work without any.
- `scripts/check-fdroid-rules.sh`, four rules, each shown to fail in section 4:
  (a) every resolved `releaseRuntimeClasspath` coordinate is in `scripts/fdroid-allowlist.txt` and none is an ad, tracking or Play Services library; it also fails when Gradle cannot resolve or fewer than 20 dependencies were parsed.
  (b) no network permission in the merged release manifest.
  (c) every sound, font, image or icon file under `app/src/main`, `design/src/main`, `audio/src/main` and `fastlane` appears by full path in `docs/provenance.csv` (sounds, relative to `assets/`) or `docs/provenance-other.csv` (everything else).
  (d) `dependenciesInfo` off in the build file and no dependency blob entry in the release APK.
- `.github/workflows/ci.yml` builds the release and runs the script; `release.yml` builds on `v*` tags, signs when secrets exist, writes a SHA-256 file and publishes.
- `fastlane/metadata/android/en-US/` title, descriptions, changelog for version code 1, 512 x 512 icon. Screenshots are not captured yet (`scripts/capture-screenshots.sh` does it).
- Docs: `README.md`, `docs/CONTRIBUTING.md`, `docs/adding-a-sound-set.md`, `docs/release/RELEASING.md`, `docs/release/fdroid-submission.md`, `docs/qa/release-smoke.md`.

### Task 28: latency test and acceptance
- `TypeToStampLatencyTest` (instrumented): types 120 characters into the real writer at 8 keys a second, measures frames with `FrameMetrics`, and asserts p95 at most 16 ms and jank at most 1 % **on a physical device only**; on an emulator it prints the numbers and skips the budget (software drawing). A second test times `SoundPoolPlayer.play()` with the real bundled sounds (p95 at most 5 ms). It is a smoke budget, not an acoustic measurement.
- `FrameMetricsMath` lives in `app/src/sharedTest/kotlin` (shared by the unit and instrumented source sets, not packaged in the app).
- `docs/qa/1.0-acceptance.md`: every evidence cell names a test class or script that exists, and each status says whether it was automated, reviewed once, walked on the emulator, or is pending a phone.

### Fixes found by the audit
- **Real app bug:** every new `MainViewModel` built a new container with its own DataStore on `settings.preferences_pb`, and DataStore throws on a second instance for one file. Finishing the activity and opening it again while the process lived (or the widget refreshing) could crash the app. Fixed with one DataStore per file for the process (`SettingsDataStoreHolder`), covered by `SettingsDataStoreHolderTest`.
- The writer's hidden text field has the test tag `writer_input`; the latency test used a tag that did not exist.
- Espresso 3.6.1 to 3.7.0 (androidTest only): 3.6.1 failed on Android 17 with `NoSuchMethodException: InputManager.getInstance`.
- README no longer says the database is encrypted; store description and changelog say Clean erase is the default; the F-Droid draft points at the real repository, no longer deletes the `dependenciesInfo` block in `prebuild`, and no longer claims a vulnerability audit or cross-machine reproducibility.
