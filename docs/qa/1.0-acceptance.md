# Enk 1.0 Acceptance Checklist

Acceptance state against "What success looks like for 1.0" in `docs/superpowers/specs/2026-11-07-enk-design.md`.

Status words used here:
- **PASS (automated)**: a test or script in the repository checks it, and the gate runs it. The evidence column names the test classes; every name below exists in the repository.
- **PASS (reviewed)**: checked by reading code or a build artifact once, with no test guarding it.
- **PASS (emulator)**: walked on the Android 17 emulator by hand once, not repeatable by a script.
- **PENDING-DEVICE**: needs a real phone. Not verified.

## 4. Known gaps and decisions still open

1. **Fast-typing race on a cold emulator.** Seen twice while auditing, not reproduced on demand. Check with a real keyboard on a phone and fast thumbs.
2. **Start animation seam and frame pacing, sound and haptics.** Not judged on a device.
3. **Pressed bead and fader 1.12x stretch.** Graphics-layer scale is not measurable in the unit tests.
4. **Search match underline** is not the specified 1.5 dp.
5. **"New note" failure path** (database error) has no test.
6. **System-dark writer paper** (design-system section 2.4) is proposed and not built. Decide for 1.0 or leave.
7. **Compact landscape with the keyboard open** (a window about 119 dp tall on the emulator): the text reflows smaller when the keyboard opens. Real keyboards on phones are not checked.
8. **First widget launch on an empty database** leaves one empty note behind.
9. **Widget sizes** are 100 x 100 dp and 250 x 100 dp, not the 170 and 360 dp in the original prompt.
10. **App name "Enk" and application id `app.enk.notes`** are not checked for availability on Google Play, F-Droid or trademark registers.
11. **Store screenshots** are not captured yet (`scripts/capture-screenshots.sh`). Rule (c) will ask for each new image to be listed in `docs/provenance-other.csv`.
12. **Cross-machine reproducible build** is not compared (see the matrix).
13. **Paid features and Drive sync** are not part of 1.0.
